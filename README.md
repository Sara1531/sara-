# Sara Project — وثيقة تصميم لعبة محاكاة هندسية واقعية ثلاثية الأبعاد

> الهدف: تطوير لعبة تعليمية/هندسية تحاكي بيئة عمل حقيقية (ورشة + مختبر)، حيث يركّب اللاعب المجسّمات الميكانيكية، ويوصل الدارات الكهربائية/الإلكترونية، ثم يبرمج النظام ويختبره ضمن محاكاة واقعية.

---

## 1) الرؤية (Product Vision)

**Sara** ليست لعبة تركيب فقط، بل منصة تدريب هندسي تفاعلية تجمع بين:

- **التجميع الميكانيكي**: تركيب واقعي مع سماحيات دقيقة.
- **الدمج الكهربائي/الإلكتروني**: توصيلات صحيحة مع كشف الأعطال.
- **برمجة التحكم**: منطق تحكم بالبلوكات أو بالنص.
- **المحاكاة والتحقق**: اختبار سلوك النظام في ظروف تشغيل متعددة.

### وعد التجربة (Experience Promise)

- يشعر اللاعب أنه يعمل داخل ورشة فعلية، وليس في لعبة مبسّطة.
- كل قطعة ثلاثية الأبعاد لها وظيفة وقيم هندسية حقيقية.
- الخطأ يُستخدم للتعلّم عبر تشخيص واضح وخطوات إصلاح عملية.

---

## 2) أعمدة الجودة الاحترافية (Quality Pillars)

### 2.1 الواقعية البصرية

- أبعاد واقعية (mm/cm) لكل قطعة.
- خامات **PBR** إنتاجية (Metal/Roughness/Normal/AO).
- مستويات **LOD** لتحسين الأداء مع الحفاظ على الجودة.
- تفاصيل تصنيع: براغي، حواف، لوحات تعريف، وآثار استخدام خفيفة.

### 2.2 الواقعية الوظيفية

لكل قطعة ورقة بيانات (Datasheet) داخل اللعبة تتضمن:

- `nominal_voltage`, `max_current`, `torque_nm`, `temp_limit_c`
- `connector_type`, `mount_pattern`, `service_life_cycles`

وتشمل الأعطال الواقعية:

- عكس القطبية.
- قصر كهربائي.
- تحميل زائد.
- احتكاك عالٍ.
- تعارض ميكانيكي.

### 2.3 الواقعية التعليمية

- التشخيص التفاعلي أهم من العقوبة.
- اللاعب يرى السبب الجذري للعطل (Root Cause) مع اقتراح إصلاح.

### 2.4 الواقعية التشغيلية

- معايير قبول رقمية: زمن الاستجابة، كفاءة الطاقة، دقة الموضع، ومعدل الأعطال.

---

## 3) دورة اللعب الأساسية (Core Gameplay Loop)

1. اختيار مهمة من موجز هندسي واقعي (Engineering Brief).
2. قراءة القيود الفنية ومعايير القبول.
3. تركيب ميكانيكي (Snap + Tolerance + Fasteners).
4. توصيل كهربائي/إلكتروني (Polarity + Load + Protection).
5. برمجة منطق التحكم (Blocks أو Script).
6. تشغيل المحاكاة ومراقبة القياسات.
7. إصلاح الأخطاء وتحسين الأداء.
8. تسليم المهمة واستلام تقرير تقييم هندسي.

---

## 4) نظام القطع والمجسّمات (Real Parts System)

### 4.1 تصنيف القطع

#### قطع ميكانيكية
- Chassis, Brackets, Shafts, Gears, Bearings, Belts, Fasteners.

#### قطع كهربائية
- PSU, Batteries, Fuses, Breakers, Relays, Limit Switches, Contactors.

#### قطع إلكترونية وتحكم
- MCU Modules, Motor Drivers, Sensors (Proximity/Temp/Pressure/Light), Actuators.

#### قطع الموائع والأنظمة الصناعية
- Pumps, Valves, Tanks, Level Sensors, Flow Sensors.

### 4.2 نموذج بيانات موحّد للقطعة (Data Contract)

```json
{
  "id": "servo_sg90_v1",
  "category": "actuator",
  "dimensions_mm": [22.8, 12.2, 28.5],
  "mass_kg": 0.013,
  "mount_points": ["m3_left", "m3_right"],
  "electrical_ports": ["vcc", "gnd", "signal_pwm"],
  "limits": {
    "voltage": [4.8, 6.0],
    "current_max_a": 0.65,
    "torque_nm": 0.18,
    "temp_c": [0, 55]
  },
  "failure_modes": ["overcurrent", "overheat", "stall"]
}
```

### 4.3 معايير قبول الأصول الفنية (Asset Acceptance)

- Pivot صحيح وموجّه وفق المحاور القياسية.
- Collision Mesh مناسب وغير مبالغ في تعقيده.
- تسمية موحّدة (`cat_type_variant_v#`).
- مواد موحّدة ضمن مكتبة خامات مشتركة (Material Library).

---

## 5) نظام التركيب الواقعي (Assembly Realism)

- **Smart Snap**: يسمح بالتركيب في نقاط صحيحة فقط.
- **Tolerance Engine**: يمنع التداخل ويتعامل مع سماحيات التصنيع.
- **Fastener Requirement**: بعض الوصلات لا تعتمد قبل إضافة المثبّتات.
- **Cable Routing**: مسارات أسلاك منطقية مع حد أقصى للانحناء.
- **Assembly Validation**: فحص آلي بعد كل خطوة مع تقرير أخطاء.

---

## 6) محاكاة الكهرباء والإلكترونيات

### نموذج محاكاة عملي (خفيف وواقعي)

- تحليل شبكة الدارة (Graph-based Solver).
- حساب الجهد/التيار لكل فرع بشكل دوري.
- نمذجة تأخير الحساسات والمشغلات.
- أنظمة حماية: Fuse Trip / Breaker Trip.

### أدوات القياس داخل اللعبة

- Multimeter (V/A/Ohm).
- Logic Monitor للإشارات الرقمية.
- Oscilloscope مبسط للمستويات المتقدمة.
- Trace Timeline لقراءة تسلسل الأحداث.

---

## 7) البرمجة داخل اللعبة

### المستوى 1 — Visual Blocks

- Input Blocks (Read Sensor, Read Switch).
- Control Blocks (If, Loop, Timer, Debounce).
- Output Blocks (Motor Speed, Relay On/Off, LED Pattern).

### المستوى 2 — Script Mode

- لغة مبسطة قريبة من Python.
- واجهة API ثابتة وسهلة الاختبار.

```txt
if sensor("tank_level") < 20:
    relay("pump").on()
elif sensor("tank_level") > 80:
    relay("pump").off()
```

### أدوات التصحيح (Debug)

- Breakpoints.
- Step Run.
- Variable Watch.
- Fault Replay.

## 8) المهام الاحترافية ومعايير القبول

| المهمة | الهدف | معايير القبول (Acceptance Criteria) |
|---|---|---|
| إضاءة ذكية | أنماط إضاءة آمنة واقتصادية | 3 أوضاع تعمل بلا أخطاء، حرارة ضمن الحدود، كفاءة ≥ 80% |
| باب منزلق | فتح/إغلاق تلقائي آمن | زمن استجابة < 0.8 ثانية، صفر تصادم، استقرار 100 دورة |
| ذراع مناولة | نقل قطعة بدقة | خطأ موضع ≤ 2 مم، نجاح ≥ 95% عبر 20 دورة |
| محطة ضخ | إدارة مستوى خزان | منع التشغيل الجاف، إنذار عطل الحساس خلال ≤ 1 ثانية |

## 9) نظام التقييم الهندسي (Engineering Scoring)

الدرجة النهائية:

- 25% صحة التركيب الميكانيكي
- 25% صحة الدارة الكهربائية
- 20% صحة منطق البرمجة
- 15% كفاءة الطاقة والزمن
- 15% الاعتمادية تحت الاختبار

### مخرجات التقييم

- تقييم نجوم (1–3).
- تقرير تشخيص للأخطاء.
- توصيات تحسين قابلة للتنفيذ.

---

## 10) الهيكل التقني المقترح (Technical Architecture)

### الطبقات الأساسية

1. **Presentation Layer**: UI/UX + Camera + Interaction.
2. **Assembly Layer**: Snap/Constraint/Fastener Systems.
3. **Simulation Layer**: Physics + Electrical Solver + Fault Engine.
4. **Control Layer**: Visual Scripting + Script Runtime.
5. **Data Layer**: Parts DB + Missions DB + Telemetry.

### تفضيل المحرك

- **Unity**: أسرع لبناء MVP.
- **Unreal**: جودة بصرية أعلى ومناسب لإصدار Premium لاحقاً.

---

6. إضافة Datasheet والحدود الهندسية.

## 12) خارطة الطريق التنفيذية (Roadmap)

### المرحلة A — Prototype (6–8 أسابيع)

- مهمتان (إضاءة + باب).
- 40 قطعة عالية الجودة.
- Visual Blocks + Multimeter.
- نظام تقييم أساسي.

### المرحلة B — Production Slice (8–12 أسبوعًا)

- إضافة الذراع + محطة الضخ.
- Script Mode + أدوات Debug متقدمة.
- تحسين الإضاءة وجودة العرض.
- مكتبة 80–100 قطعة.

### المرحلة C — Beta (10–14 أسبوعًا)

- تحسين الأداء والتوافق.
- توسيع المهام الصناعية.
- Telemetry + Analytics لضبط التوازن.

---

## 13) مؤشرات النجاح (KPIs)

- معدل إكمال المهام الأولى > 70%.
- انخفاض أخطاء التوصيل 30% بعد 3 مهام.
- متوسط زمن المهمة الثانية أقل 20% من الأولى.
- رضا المستخدم عن واقعية المجسمات والقطع ≥ 4/5.

---
